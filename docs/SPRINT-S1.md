# Спринт S1 «Канонизация» — пользовательские истории

**Версия артефакта:** 2.0 (переписан по итогам планирования 19.11.2026)
**Период:** 20.11.2026 – 03.12.2026
**Статус:** ВЫПОЛНЕН
**Место:** `docs/SPRINT-S1.md`

---

## 1. Цель спринта

Привести уже построенную систему (граф, tools, eval — всё в репо) в соответствие
с единственным каноном: решения ревизии 6.4 + журнал `docs/DECISIONS.md`.
Спринт **не строит** новые этапы 2–5 и **не переделывает** существующие —
он канонизирует контракт, набор и журнал друг с другом.

**Результат спринта:** репозиторий, в котором код, GoldenSet и журнал решений
согласованы; CI ловит любой будущий дрейф набора; полный регресс зелёный.

---

## 2. Решения по планированию (зафиксированы 19.11.2026)

Эти решения сняли вопросы, возникшие при сверке артефакта с состоянием репозитория.

| № | Вопрос | Решение |
|---|---|---|
| П1 | Регресс-гейт: baseline 393 или текущие 880? | **880.** Полный прогон текущей сюиты (880 passed на 19.11.2026) без регрессии относительно HEAD. Откат к 393 не требуется — это история, а не проверяемое состояние. |
| П2 | US-3 и US-6 «уже сделаны»? | **Верификация, не чекмарк.** Код писался до решений 6.4 — 880 зелёных тестов не гарантируют соответствия канону. Обе истории выполняются как контрактный аудит по чек-листам (см. истории). Найденные дрейфы правятся как дефекты внутри истории, без переписывания. |
| П3 | Порядок исполнения | **US-1 → US-2 → US-4 → US-5**, коммиты по историям. US-3 и US-6 — верификация, параллельно. **Жёсткая зависимость:** US-4 не начинается до US-2 (нормализация top-кейсов зависит от итогового дефолта limit). |
| П4 | Скоуп: граф/tools/eval в репо | **Подтверждено.** Спринт их не переделывает. Вне скоупа только их *развитие*; соприкасающиеся части проверяются в US-3/US-6. |
| П5 | Оценка пересчитана | 23 sp → **14 sp**: объём изменился с «работа с нуля» на «доработка + аудит». |

### Контекст состояния репозитория (для агента-исполнителя)

Репозиторий опережает прежний план: этапы 2–5 реализованы (граф, tools,
eval-скрипты, live-прогон, judge, per-call лимиты, версия 0.8.0, 880 passed).
Поэтому в спринте:

- **новая работа:** US-1, US-2, US-4, US-5;
- **верификация:** US-3, US-6 — коммиты с пометкой «verified + findings», не «done».

Тесты зелёные против кода, а не против решений 6.4 — это и есть главный риск,
который закрывает контрактный аудит.
