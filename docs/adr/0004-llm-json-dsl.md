# ADR 0004: Граница LLM → код — JSON-DSL и `dispatch_intent`

- **Статус:** принято
- **Дата:** 2026-10-23
- **Контекст:** архитектурный принцип — LLM не считает числа. Нужен явный, проверяемый контракт между «переводом вопроса» и расчётом; при этом Pydantic/LangChain в окружении не установлены, а MVP не должен зависеть от тяжёлых фреймворков.

## Решение

1. LLM возвращает только JSON-DSL: `{"intent": "...", "params": {...}}`.
2. В `analytics.py` есть реестр `INTENT_REGISTRY` (имя → функция) и `INTENT_PARAMETERS` (имя → допустимые параметры).
3. `dispatch_intent(intent, df, params)` валидирует имя интента, лишние и отсутствующие параметры и вызывает функцию.
4. Pydantic-модели добавляются как адаптер на следующем шаге, когда появится LLM-слой; реестр остаётся источником истины для схемы инструмента.

## Обоснование

1. **Проверяемость:** неверный интент или параметр — понятная ошибка, а не «странный отчёт».
2. **Детерминизм:** расчёт полностью воспроизводим по DSL; LLM не влияет на числа.
3. **Слабая связанность:** реестр не требует LangChain/Pydantic; интеграция — тонкая обёртка.
4. **Защита от «сырых» ответов модели:** `params` обязан быть объектом, лишние ключи отклоняются, обязательные проверяются по сигнатуре функции.
5. **Понятность для UI:** один и тот же DSL используется Streamlit-приложением и внешними агентами.

## Пример DSL

```json
{"intent": "top_bottom_products",
 "params": {"metric": "revenue", "limit": 10, "ascending": false,
            "start_date": "2024-01-01", "end_date": "2024-12-31"}}
```

```json
{"intent": "counterparty_dynamics",
 "params": {"period1": ["2023-01-01", "2023-12-31"],
            "period2": ["2024-01-01", "2024-12-31"],
            "metric": "revenue", "top_n": 10}}
```

## Последствия

- Валидация параметров: `ValueError` с перечнем допустимых/недостающих параметров.
- Новый интент = функция + запись в `INTENT_REGISTRY`/`INTENT_PARAMETERS` + строка в документации DSL.
- Pydantic-схемы (следующий шаг) генерируются из реестра или дублируют его осознанно; при расхождении источник истины — код + тесты.
- Для LLM-промпта достаточно передать перечень интентов и параметров из `INTENT_PARAMETERS` (без описания внутренних функций).
