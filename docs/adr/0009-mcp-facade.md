# ADR 0009: MCP-фасад над JSON-DSL

- **Статус:** принято
- **Дата:** 2026-11-13
- **Контекст:** продукт уже имеет детерминированный движок (`dispatch_intent` → pandas),
  но аналитику нужно доставлять в чат через ИИ-агента (Hermes Agent), а не только
  через Streamlit. Агент умеет вызывать инструменты по протоколу MCP. Возникает
  соблазн дать агенту один универсальный инструмент `execute_dsl(json)`, чтобы не
  описывать каждый срез отдельно.

**Рассмотренные варианты**

1. `execute_dsl(json)` — один инструмент, внутри `dispatch_intent`.
2. Типизированные MCP-инструменты по числу срезов (`total`, `top_bottom_products`, …).
3. LangChain StructuredTool / собственный HTTP-сервис.
4. MCP-сервер как отдельный сервис с состоянием и базой.

## Решение

Выбран вариант 2 — **тонкий MCP-фасад над существующим JSON-DSL**:

- 12 прикладных инструментов (7 срезов + 4 инструмента данных + `returns_alert`),
  плюс 4 служебных метода MCP SDK;
- `execute_dsl` **не публикуется**: произвольный JSON от модели — это второй,
  неконтролируемый контракт и расширение поверхности атаки;
- валидация параметров — та же, что в движке (`INTENT_PARAMETERS`, Pydantic);
- числа считает только движок; сервер добавляет детерминированные итоги
  (сумма/доля/мин/макс), чтобы модель не складывала строки;
- каждый ответ несёт период и дату данных; нет среза — отказ, а не похожий ответ;
- JSONL-аудит каждого вызова, read-only доступ к витрине;
- транспорт v1 — stdio (процесс-потомок клиента), состояние — текущая витрина.

## Обоснование

1. **Контракт уже существует.** JSON-DSL — проверенный контракт LLM → код
   ([ADR 0004](0004-llm-json-dsl.md)); MCP-фасад лишь переоткрывает его типизированно,
   не создавая второго языка запросов.
2. **Отказы вместо подмены.** Типизированный инструмент не может «сымитировать»
   неподдерживаемый вопрос: маржа/средний чек получают отказ, а не похожий срез.
3. **Портируемость.** MCP — стандарт; Hermes — первый клиент, но не единственный.
   LangChain-обёртка привязывает к фреймворку и не даёт инструментов «из коробки».
4. **Минимальная поверхность.** Нет SQL, нет записи, нет произвольных фильтров;
   allowlist путей витрины; отключённые toolsets у агента.
5. **Наблюдаемость.** Аудит позволяет доказать, что ответ получен инструментом,
   а не сгенерирован моделью.

## Последствия

- Каждый новый срез требует явного инструмента и теста — это осознанная цена.
- Контракт ответа нужно версионировать ([ADR 0011](0011-answer-contract-version.md)).
- Одна витрина на процесс; мультипользовательская изоляция — отдельное решение.
- `execute_dsl` может появиться только как внутренний debug-инструмент с
  отдельным allowlist и аудитом, не для агента.
- Проверка: `tests/test_mcp_server.py`, `tests/test_mcp_stdio.py`,
  `tests/test_answer_contract.py`.
