# ADR 0006: LLM-провайдеры и офлайн-фолбэк

- **Статус:** принято
- **Дата:** 2026-10-23
- **Контекст:** шаг 2 требует LLM, которая переводит вопрос в JSON-DSL. Заказчик назвал DeepSeek/OpenAI/Ollama как возможные варианты; в окружении нет ни SDK, ни ключей, а PyPI для установки пакетов недоступен. Приложение должно запускаться и демонстрироваться без ключа API.

## Решение

1. **Единый протокол** — OpenAI-совместимый Chat Completions (`POST {base_url}/chat/completions`). Через него работают OpenAI, DeepSeek и Ollama (`/v1`).
2. **Клиент на стандартной библиотеке** (`urllib.request`), без SDK и внешних зависимостей; настройки — переменные окружения (`LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_TIMEOUT`, `LLM_TEMPERATURE`).
3. **Pydantic 2 — единственная жёсткая зависимость LLM-слоя**: модели с `extra="forbid"` повторяют контракт `INTENT_REGISTRY`/`INTENT_PARAMETERS`, плюс интент `clarification`.
4. **Офлайн-фолбэк** `RuleBasedPlanner`: если провайдер не настроен, вопрос разбирается детерминированными правилами (типовые формулировки 5 интентов, годы/даты/месяцы, «по сравнению с»), а неоднозначные вопросы возвращают `clarification`.
5. **Один ремонт JSON:** при ошибке валидации модели отправляется сообщение с описанием ошибки и просьбой вернуть корректный JSON; после второй ошибки — дружелюбный отказ (UI показывает 5 интентов и примеры).

## Обоснование

1. **Нет привязки к вендору:** переключение провайдера — переменная окружения, код не меняется.
2. **Нулевые зависимости для HTTP:** нет `openai`/`requests`, меньше рисков установки; JSON-режим включается опционально (не все провайдеры его поддерживают — есть повтор без `response_format`).
3. **Демо без ключа:** приёмка UI не блокируется ожиданием ключа; офлайн-режим честно подписан в интерфейсе.
4. **Безопасность контракта:** Pydantic отклоняет неизвестные поля/интенты, поэтому «фантазии» модели не доходят до pandas.
5. **Тестируемость:** `LLMPlanner` принимает fake-клиент, поэтому валидация, «починка» и ошибки проверяются без сети; `RuleBasedPlanner` покрыт 8 сценариями.

## Рассмотренные альтернативы

- **SDK OpenAI** — отклонено: лишняя зависимость, для Ollama/DeepSeek всё равно нужен base_url.
- **Ollama native API** (`/api/chat`) — отклонено: нарушает единый протокол; Ollama поддерживает `/v1`.
- **Только LLM, без правил** — отклонено: приёмка и тесты зависели бы от ключа/сети.
- **Pydantic v1** — отклонено: в доступном окружении pydantic 2.14; v2 даёт discriminated union и `TypeAdapter`.

## Последствия

- В `requirements.txt` добавлены `streamlit` и `pydantic`; для UI нужен интерпретатор с pandas+streamlit+pydantic.
- `check_schema_sync()` в приложении сверяет модели с `analytics.INTENT_PARAMETERS`; `smoke_test.py` (раздел 12) сверяет `docs/intent_schema.json` с `analytics`, `smoke_llm.py` — модели с той же схемой.
- Офлайн-правила не являются полноценной заменой LLM: покрывают типовые формулировки, остальное — `clarification`.
- При подключении LangChain (следующий шаг) `INTENT_REGISTRY`/`parse_plan_json` остаются источником истины; LangChain-обёртка будет адаптером, а не вторым контрактом.
