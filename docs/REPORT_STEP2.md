## 1. Резюме

Заказчик передал обратную связь: «шаг 1 завершён, нужен шаг 2 — интерфейс и слой связи с языковой моделью». Инкремент закрывает четыре пункта ТЗ:

1. **Pydantic-модели** для валидации JSON, который возвращает LLM (на основе `INTENT_REGISTRY`).
2. **Системный промпт** для DeepSeek/OpenAI/Ollama с обработкой неоднозначных вопросов (`intent: "clarification"`).
3. **Streamlit UI**: выбор источника, качество данных, вопрос, таблица, график, блок «Как я это посчитал».
4. **Fallback**: невалидный JSON или ошибка `dispatch_intent` → дружелюбное сообщение и список 5 интентов.

Дополнительно сделан **детерминированный офлайн-планировщик** (`RuleBasedPlanner`), чтобы демонстрация и приёмка работали без ключа API, и **артефакт схемы** `docs/intent_schema.json` для промпта/LLM-инструмента.

Проверено: `smoke_test.py` — 12 разделов, 59 проверок, PASSED; `smoke_llm.py` — 85 проверок, PASSED; сквозная связка «DSL → `dispatch_intent`» — все 5 интентов на витрине 1С. UI в песочнице не запускался: Streamlit не установлен, PyPI/TLS из shell закрыты.

## 3. Что реализовано

### 3.1. Pydantic-модели (`llm_agent.py`)

- Модели параметров: `TopBottomParams`, `TimeseriesParams`, `CounterpartyDynamicsParams`, `GroupDynamicsParams`, `TotalParams`; у всех `extra="forbid"`.
- Модели интентов: `TopBottomPlan`, `TimeseriesPlan`, `CounterpartyDynamicsPlan`, `GroupDynamicsPlan`, `TotalPlan`, `ClarificationPlan`; объединены в `IntentDSL` через discriminated union по полю `intent`.
- Валидация: даты ISO и `ДД.ММ.ГГГГ`, начало периода ≤ конец, `limit/top_n` 1…1000, метрика `revenue|quantity`, частота ряда, `sort_by`, `only_drops`; лишние поля отклоняются.
- `to_dispatch_params()` превращает валидированный DSL в аргументы `dispatch_intent` (даты остаются `date`).
- `check_schema_sync()` сверяет параметры моделей с `analytics.INTENT_PARAMETERS`; `docs/intent_schema.json` — та же схема для интеграций.

### 3.2. Промпт и LLM-провайдеры

- Системный промпт: только JSON `{"intent": ..., "params": ...}`, без markdown; выручка по умолчанию без НДС; даты ISO; правила для двух периодов; 5 few-shot примеров; `clarification` при нехватке данных.
- История диалога (последние 6 сообщений) и профиль данных (строки, диапазон дат, товары, контрагенты, источник) добавляются в сообщения.
- Клиент на стандартной библиотеке: OpenAI-совместимый `POST {base_url}/chat/completions`; провайдеры `openai`, `deepseek`, `ollama`; настройки через env; `response_format` опционален, при отказе провайдера — повтор без него.
- Разбор ответа: JSON из текста/```-блока; при ошибке — одна попытка «починки» с описанием ошибки; после второй ошибки — `AgentDecision(ok=False, error=...)`.
- Офлайн-фолбэк: `RuleBasedPlanner` разбирает типовые вопросы (топ, месяцы/кварталы/годы, контрагенты, группы, итог, «по сравнению с», последний месяц) и возвращает `clarification`, если данных не хватает.

### 3.3. Streamlit UI (`app.py`)

- Сайдбар: выбор источника (1С CSV / Excel `тест.xlsx` / загрузка файла), `get_data_quality` (строки без даты, возвраты), режим LLM, сброс истории.
- Основное окно: история диалога, поле вопроса, кнопка «Спросить».
- Обработка: планировщик → Pydantic → `dispatch_intent` → DataFrame.
- Отображение: текстовая сводка (без LLM), `st.dataframe`, график (`bar_chart` для топов и динамики, `line_chart` для ряда), `st.metric` для итога, expander «Как я это посчитал» с JSON-DSL и сырым ответом модели.
- Fallback: уточняющий вопрос (`clarification`), дружелюбная ошибка со списком 5 интентов и примерами, детали в раскрывающемся блоке.

## 5. Принятые решения и отклонения

1. **Офлайн-фолбэк (дополнение к ТЗ).** `RuleBasedPlanner` позволяет демонстрировать и принимать UI без ключа LLM; в интерфейсе режим честно подписан. Обоснование — [ADR 0006](adr/0006-llm-providers.md).
2. **OpenAI-совместимый протокол вместо SDK.** Меньше зависимостей, один код для OpenAI/DeepSeek/Ollama; переключение — переменная окружения.
3. **Pydantic v2** (доступная версия): discriminated union, `TypeAdapter`, `extra="forbid"`.
4. **LangChain StructuredTool не сделан.** Фреймворк не установлен; контракт (`INTENT_REGISTRY`, `parse_plan_json`, `dispatch_intent`) готов, адаптер — следующий шаг. Это единственный пункт ТЗ, вынесенный за инкремент.
5. **UI не запускался в песочнице.** Streamlit/Pydantic нельзя установить (PyPI/TLS из shell), Pydantic и pandas — в разных интерпретаторах; UI проверен статически, LLM-слой — тестами.

## 10. После ревью: исправление `limit` (2026-10-23)

### Проблема

В `RuleBasedPlanner.plan` количество для топ/антитопа извлекалось регуляркой
`(?:топ[-\s]?|первые\s+)?(\d{1,3})` **без границ слова**. В вопросе
«Какие товары продаются хуже остальных за 2024 год, топ 5?» она находила `202`
из `2024`, и пользователь получал `limit=202`. Ошибка проявлялась только на
живых формулировках (в тестах шага 2 такого вопроса не было).

### Исправление

Добавлена функция `_extract_limit(text) -> int`:

1. явное количество: «топ 5», «топ-10», «первые 3»;
2. число перед существительным: «5 товаров», «7 худших», «20 позиций»;
3. одиночное число 1–999, но **не** внутри даты (`21.09.2023`), года (`2024`)
   и не перед единицей периода (`2 квартала`, `3 месяца`);
4. диапазон 1…1000, иначе значение по умолчанию 10.

Дополнительно в детекцию топ-интента добавлены «первые/top», а интент «итог»
больше не перехватывает вопросы вида «сколько продали за последний месяц»
(они относятся к `total` с периодом из профиля данных).

### Тесты

Добавлен [`test_planner.py`](../tests/test_planner.py) — **18 pytest-тестов** (позже перенесён в `tests/` и расширен до 81 теста на шаге 3):
5 интентов, 6 краевых случаев и 3 регрессии на баг:
- «за 2024 год, топ 5» → `limit=5`;
- год без количества → `limit=10`;
- дата `21.09.2023` → `limit=10`.

### Приёмка

Инструкция локального запуска UI и 5 контрольных вопросов с ожидаемыми
интентами и числами — [UI_ACCEPTANCE.md](UI_ACCEPTANCE.md). Регрессия бага
включена в чек-лист приёмки.

### Проверено
