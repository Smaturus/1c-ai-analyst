# Контракт данных

Документ фиксирует схему витрины, семантику колонок, инварианты и правила
качества. Любой источник (демо-данные, Excel, 1С, будущие) обязан возвращать
данные в этом контракте.

> **Лицензии:** реальные выгрузки 1С (`тест.xlsx`, `1c_export/*.csv`) в
> репозитории отсутствуют и в публичную историю не включаются. В комплекте —
> только синтетический `sample_data.csv`, который генерируется
> `generate_synthetic_data.py`.

## 1. Витрина

### 1.1. Excel-источник (`load_and_clean_1c_report`)

| Колонка | Тип | Семантика |
|---|---|---|
| `date` | `datetime64[us]`, `NaT` допустим | Дата документа; `NaT` — даты в выгрузке нет |
| `product` | `string` | Товар (номенклатура) без склада, `Не указано` при пустом |
| `counterparty` | `string` | Контрагент/партнёр, `Не указано` при пустом |
| `quantity` | `float64` | Количество, отрицательное — возврат; `NaN → 0.0` |
| `revenue` | `float64` | Выручка без НДС (`net`, по умолчанию) или с НДС (`gross`); `NaN → 0.0` |

Порядок колонок: `date, product, counterparty, quantity, revenue`. Индекс — `RangeIndex`, сортировка по `date, product, counterparty`, строки с `NaT` в конце.

### 1.2. Источник 1С (`load_vitrina`)

К пяти колонкам добавляется:

| Колонка | Тип | Семантика |
|---|---|---|
| `product_group` | `string` | Товарная группа — ближайшая группа-родитель в справочнике «Номенклатура»; `Без группы` для товаров в корне справочника |

Порядок: `date, product, counterparty, quantity, revenue, product_group`.

### 1.3. Синтетический демо-источник (`load_sample_vitrina`)

`sample_data.csv` (600 строк, 2023–2024) уже содержит `product_group`, поэтому
загружается напрямую в схему витрины: `date, product, counterparty, quantity,
revenue, product_group`. Это единственный источник данных, который лежит в
публичном репозитории; он детерминированно генерируется
`generate_synthetic_data.py` и не содержит коммерческой информации.

## 2. Инварианты

1. Контрольные суммы витрины равны итогам источника. Для демо-данных:
   выручка **99 708 100,00**, количество **5 315** (600 строк, 2023–2024);
   эти суммы сверяет `smoke_test.py`. Для собственных выгрузок 1С инвариант
   проверяется на стороне пользователя (реальные контрольные суммы в
   репозиторий не включены).
2. Отрицательные значения (возвраты, сторно) **не отбрасываются**.
3. При заданных границах периода строки с `NaT` не участвуют в расчёте; при задании только одной границы — вторая подставляется по фактическим данным (для `get_total`).
4. `delta_pct` рассчитывается только при `period1_value > 0`; иначе `NaN` (проценты от нулевой/отрицательной базы бессмысленны).
5. Пустые результаты возвращаются типизированными DataFrame с теми же колонками.
6. Операции над витриной не мутируют исходный DataFrame (копии там, где нужно).

## 3. Числовые соглашения

- Денежные значения — `float64`, без округления в коде (округление — задача отображения).
- `delta` = `period2_value − period1_value`.
- `delta_pct` = `(period2 − period1) / period1 × 100` при `period1 > 0`.
- `direction`: `up`, `down`, `flat`, `new` (было 0, стало ≠0), `lost` (было ≠0, стало 0).
- `share_pct` (топ/антитоп) = значение / сумма по всем строкам × 100.
- Валюта — рубли (в выгрузке нет валюты; для мультивалютных баз потребуется отдельный разрез).

## 4. Семантика периода

- Период задаётся парой дат включительно: строка, `date`, `datetime`, `pd.Timestamp`, `np.datetime64`; строки — `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`.
- Время обрезается до дня.
- `compare_periods` принимает два периода; перепутанный порядок даёт предупреждение, `start > end` — `ValueError`.

## 5. CSV-контракт выгрузки 1С

Файлы `sales_1c.csv` и `nomenclature_1c.csv` создаются `onec_source.py`
локально и в публичный репозиторий не коммитятся. Формат: UTF-8, CSV с
заголовком в первой строке, разделитель — запятая.

`sales_1c.csv`:

| Колонка | Пример | Комментарий |
|---|---|---|
| `date` | `2023-09-21` | ISO-дата |
| `product` | `Кондиционер ELEKTA` | Наименование номенклатуры |
| `product_group` | `Вентиляторы, пылесосы, кондиционеры` | Ближайшая группа |
| `product_group_path` | `Торговая деятельность / Бытовая техника / …` | Полный путь |
| `counterparty` | `Ассоль` | Партнёр |
| `quantity` | `1.0` | Количество |
| `revenue_net` | `20000.00` | Выручка без НДС |
| `revenue_gross` | `24000.00` | Выручка с НДС |
| `operation` | `Реализация` | Хозяйственная операция |
| `registrar` | `Реализация товаров и услуг ТД00-000029 от …` | Документ-регистратор |
| `organization` | `Торговый дом "Комплексный"` | Организация |

`nomenclature_1c.csv`: `name, parent, is_group, product_group, product_group_path` (253 позиции, 61 группа).

## 6. Правила качества и признаки

- Демо-данные: 0 строк без даты, 60 строк с отрицательной выручкой (10 %, возвраты), отрицательных значений в нулевых строках нет.
- Excel (для собственных выгрузок): возможны строки без даты и отрицательные суммы — они сохраняются, но не попадают в периодическую аналитику.
- `get_data_quality(df)` возвращает таблицу: всего строк, с датой/без даты, доля выручки без даты, выручка без даты, нулевые/отрицательные строки, минимальная/максимальная дата (ISO-строки, JSON-безопасно).
- Предупреждения (`UserWarning`): при загрузке Excel — о строках без даты и возвратах; при `filter_by_period` с границами — сколько строк/выручки исключено.

## 7. Требования к новому источнику

Новый загрузчик обязан:

1. Вернуть DataFrame с колонками `date, product, counterparty, quantity, revenue` (и `product_group`, если группы доступны).
2. Привести типы: `date` — datetime, текст — `string`, числа — `float64`.
3. Сохранить отрицательные значения и не терять строки без даты (или явно документировать потерю).
4. Пройти `smoke_test.py` без изменения контрольных сумм.
