## 1. Резюме

Инкремент закрывает UX-проблемы диалога «вопрос → уточнение → ответ», найденные при ручной приёмке:

1. **Quick Replies.** Варианты ответа на уточняющий вопрос (`intent="clarification"`) выводятся кликабельными «таблетками» через `st.pills` вместо маркированного списка. Выбор варианта подставляет текст в поле и автоматически отправляет вопрос; запасной путь без `st.pills` — компактные кнопки `type="tertiary"`.
2. **Умный выбор текста.** Новый модуль [`clarification.py`](../../clarification.py) решает, что показать в поле: если вторая часть сама распознаётся планировщиком как полный вопрос — только она; если это фрагмент («2024 год», «2023 и 2024») — склейка с исходным вопросом. Спорный случай решает LLM-классификатор (только при включённой LLM), ошибка LLM → безопасная склейка.
3. **Отправка по Enter.** Поле вопроса и кнопка «Спросить» помещены в `st.form` (`border=False`), поэтому Enter в поле отправляет вопрос. Кнопка очистки «✖️» вынесена за пределы формы и только очищает поле.
4. **Graceful Degradation.** Счётчик `clarification_rounds` ограничивает уточнения двумя раундами; после этого выполняется детерминированная ближайшая интерпретация (`force_interpretation`, только правила, без LLM) и показывается плашка «Уточнения исчерпаны — показываю как понял…». Составной запрос («топ за 2023 и за 2024») сводится к одному показателю за общий диапазон. Решение зафиксировано в [ADR 0007](../adr/0007-graceful-degradation.md).

Ключевые числа: **183 pytest-теста** (было 152 на конец шага 3), `smoke_llm.py` — 86 проверок, `smoke_test.py` — PASSED. Принцип «LLM не считает числа» сохранён: LLM выбирает только текст/параметры, расчёты — pandas.

## 3. Что реализовано

### 3.1. Quick Replies (`st.pills`)

- `render_clarification` показывает варианты как `st.pills` (single-select). Запасной путь без компонента — кнопки `type="tertiary"`.
- Callback `apply_suggestion` запоминает выбранный вариант (`clarification_answer`) и запускает перерисовку; текст в поле записывается в `main()` **до создания виджета** — прямая запись после создания виджета запрещена Streamlit.
- `st.rerun()` в callback не нужен: изменение виджета само запускает перерисовку.

### 3.2. Умный выбор текста (`clarification.choose_clarified_text`)

Порядок решений:

1. Пустое уточнение — остаётся исходный вопрос.
2. Нет исходного вопроса — остаётся уточнение.
3. Уточнение уже содержит исходный вопрос — остаётся уточнение.
4. Вторая часть — полный вопрос по правилам планировщика → в поле, расчёт и историю уходит **только она**.
5. Вторая часть — явный фрагмент → **склейка через пробел**.
6. Спорный случай (похоже на вопрос, но правила не распознали) → LLM-классификатор (один JSON-ответ `{"self_sufficient": bool}`, только при включённой LLM); ошибка/мусор → безопасная склейка.

Поле, отправленный запрос и запись в истории — один и тот же текст (`clarification_source`: `answer`/`merged`/`llm`).

### 3.3. Отправка по Enter

```python
question_col, clear_col = st.columns([5, 1], vertical_alignment="bottom")
with question_col:
    with st.form("question_form", clear_on_submit=False, border=False):
        question = st.text_input("Вопрос к данным", key="question_input", ...)
        submitted = st.form_submit_button("Спросить", type="primary")
with clear_col:
    st.button("✖️", help="Очистить поле", on_click=clear_question)
```

Ограничение шага 3 («Enter не отправляет вопрос», отказ от формы) снято: очистка вынесена за пределы формы. Особенность AppTest (внутри формы `set_value` не применяется до отправки) учтена в тестах через `st.session_state`.

### 3.4. Graceful Degradation

- `MAX_CLARIFICATIONS = 2`, счётчик `clarification_rounds` (сбрасывается после ответа/ошибки, при «✖️» и «Очистить историю»).
- После второго уточнения: `force_interpretation` — детерминированные правила без LLM; при успехе — результат + жёлтая плашка; если правила не выбрали интент — понятная ошибка и список вопросов.
- Составной запрос сводится к одному показателю за общий диапазон; ограничения описаны в [ADR 0007](../adr/0007-graceful-degradation.md).

## 5. Ограничения

1. **Составной запрос не поддерживается по смыслу:** DSL — один интент на запрос; «два отдельных рейтинга» не строятся, fallback сводит к одному диапазону (2023–2024), а не к первому периоду и не к двум таблицам.
2. **Интерпретация правил может отличаться от замысла** (метрика/интент); плашка предупреждает, JSON в «Технических деталях» показывает фактические параметры.
3. **Лимит уточнений — на сессию UI** (`st.session_state`), не на пользователя и не в БД.
4. **LLM-классификатор** — только при включённой LLM, один вызов, без повторов; ошибка → склейка.
5. **Уровень 2 всегда детерминированный** — в LLM-режиме вынужденная интерпретация может отличаться от «стиля» LLM.
6. **Деградация не покрывает ошибки данных** (битый файл, отсутствующий снимок 1С) — там нет «ближайшего» результата.
7. **Частичных результатов нет** — нельзя показать один из двух рейтингов с пометкой.
