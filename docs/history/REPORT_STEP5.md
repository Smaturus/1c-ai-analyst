## 1. Резюме

Проведён стресс-тест: 10 запросов, намеренно ломающих типовые сценарии (отрицательная выручка, составные запросы, кавычки в названиях, условия «больше N», неподдерживаемые показатели, пустой период, противоречивые формулировки). Каждый запрос проверен в офлайн-режиме и, где доступен ключ, в LLM-режиме (DeepSeek).

Найдено и исправлено **7 дефектов**:

1. Запрос про отрицательную выручку подменялся антитопом (не было интента) → добавлен `negative_revenue` + `guard_decision`.
2. Игнорировался фильтр по конкретному товару → добавлен `product_filter`.
3. Игнорировался фильтр по товарной группе → добавлен `group_filter` (включая паттерн «группа "…"»).
4. Условие «база/выручка больше N» не учитывалось → добавлен `min_base_revenue`.
5. «Средний чек» ошибочно превращался в обычный топ → теперь честный `clarification`.
6. Пустой период показывал пустую таблицу без объяснения → сообщение с доступным диапазоном дат.
7. Противоречивая сводка `total` при фильтре без совпадений («найдено 1 записей… строк 0») → «По фильтру «…» данных не найдено за выбранный период».

Дополнительно: офлайн-ответы без указания дат стали предсказуемыми (дефолтный период 2023-01-01…2024-12-31 или диапазон из профиля данных), а в «Технических деталях» JSON можно копировать одной кнопкой.

## 2. Программа стресс-теста (10 запросов)

| № | Запрос | Режим | Ожидание | Результат после исправлений |
|---|---|---|---|---|
| 1 | `Сколько мы продали за 2024 год?` | офлайн/LLM | итог за период | «Итог за период»: выручка/количество/строки, без подмены интента |
| 2 | `покажи все отрицательные выручки январь–июнь 2024 товары с отрицательной выручкой` | LLM/офлайн | только отрицательные суммы | интент `negative_revenue`, красные бары, сводка «Общая сумма возвратов», в таблице только `revenue < 0` |
| 3 | `Сравни топ-5 товаров за 2023 и 2024 годы` | офлайн/LLM | два рейтинга в одном ответе | интент `compare_top_products` (L4L): места, выручка за оба года, дельта, статусы «вошёл/выпал/поднялся/опустился» |
| 4 | `Сколько продали «Телевизор Zeta» за 2024` | офлайн/LLM | фильтр по товару | `total` + `product_filter="Телевизор Zeta"`; итог 11 990 000,00 ₽, сводка «По фильтру «…» найдено N записей» |
| 5 | `Топ-5 товаров в группе «Бытовая техника» за 2024` | офлайн/LLM | фильтр по группе | `top_bottom_products` + `group_filter`; поддержан и вариант `группы "…"` с прямыми кавычками |
| 6 | `У каких контрагентов выручка в 2023 была больше 100к и упала в 2024` | офлайн/LLM | фильтр по базе | `counterparty_dynamics` + `min_base_revenue=100000`, только контрагенты с базой ≥ 100 000 ₽ |
| 7 | `Сравни средний чек за 2024` | офлайн/LLM | честный отказ | `clarification`: «Расчёт среднего чека не поддерживается. Доступны только суммарная выручка и количество.» |
| 8 | `Динамика по месяцам за 2030` | офлайн | объяснение пустого периода | «За выбранный период данных нет. В текущем источнике данные доступны с 01.01.2023 по 28.12.2024.» |
| 9 | `Покажи что-нибудь интересное` | офлайн/LLM | уточнение без падения | `clarification` с кликабельными Quick Replies; после двух уточнений — детерминированный fallback |
| 10 | `Сколько продали «НетТакого» за 2024` | офлайн | корректное «нет данных» | «По фильтру «НетТакого» данных не найдено за выбранный период» (без противоречия «найдено 1 записей… строк 0») |

Проверки выполнялись на синтетической демо-витрине `sample_data.csv` (600 строк, 2023–2024); LLM-режим — вручную на DeepSeek с теми же формулировками.

## 3. Что изменено

### 3.1. Аналитика (`analytics.py`)

- `product_filter` — `get_top_bottom_products`, `get_total`, `get_timeseries`;
- `group_filter` — `get_top_bottom_products`, `get_group_dynamics` (поиск по `product_group`/`product_group_path`);
- `min_base_revenue` — `compare_periods` и `get_counterparty_dynamics` (фильтр `period1_value >= N` до сортировки/`top_n`);
- `get_negative_revenue` — интент «Отрицательная выручка / возвраты»: только `revenue < 0`, агрегат по товару/контрагенту (`revenue`, `rows_count`, `quantity`);
- `compare_top_products` — L4L-сравнение топов двух периодов;
- все новые параметры зарегистрированы в `INTENT_PARAMETERS`.

### 3.2. LLM-слой (`llm_agent.py`)

- Pydantic-поля и модели новых параметров/интентов; `IntentDSL` — 7 интентов;
- промпт: правила про товар/группу/«базу больше N», запрет `top_bottom_products` для отрицательной выручки, отказ для среднего чека, 6 Few-Shot примеров;
- офлайн-правила: извлечение названий из кавычек, «группа/категория "…"», числа из «больше 100к/1 млн», честный отказ на «средний чек», дефолтные даты при отсутствии периода;
- `guard_decision` — защита от подмены запроса про отрицательную выручку антитопом.

### 3.3. UI (`app.py`)

- `build_summary`: пустой период объясняет доступный диапазон дат; при активном фильтре — «По фильтру «…» найдено N записей»; для `total` с `rows_count == 0` — корректное «данных не найдено»;
- отрицательная выручка: красные горизонтальные бары и сводка «Найдено N товаров… Общая сумма возвратов»;
- L4L: таблица со статусами и grouped bar;
- JSON-DSL в «Технических деталях» — блок `st.code` со встроенной кнопкой копирования;
- демо-лимиты LLM в сайдбаре (`rate_limiter.py`), кнопка «Сбросить лимит (Демо-режим)».

## 5. Ограничения

1. **Составные запросы:** DSL — один интент на запрос; сравнение двух рейтингов покрыто `compare_top_products`, остальные multi-intent-сценарии (например, топ + динамика в одном ответе) не поддерживаются.
2. **Отрицательная выручка:** в витрине нет `operation`/`registrar`, поэтому «возврат» и «сторно» не разделяются — показывается агрегат отрицательных сумм.
3. **Фильтры — подстрока** без учёта регистра (не полнотекстовый поиск); `group_filter` требует колонку `product_group`/`product_group_path`.
4. **`min_base_revenue`** поддержан только у `counterparty_dynamics`.
5. **Средний чек** — честный отказ; отдельного расчёта нет.
6. **Лимиты LLM** — 15 запросов/сессия и 100/день; при исчерпании — офлайн-правила (текст, а не числа, модели не вызывается).
7. **LLM-режим** проверен вручную (DeepSeek); автотесты используют fake-клиент и офлайн-правила.
