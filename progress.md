## Итоги

- **Загрузчик Excel** (`data_loader.py`): шапка 7 строк, удаление «Итого», разбор склеек `A`/`V`, дата из `E` регуляркой, типы, валидация структуры, предупреждения о качестве. Контрольные суммы совпали с «Итого» файла.
- **Аналитика** (`analytics.py`): 5 интентов, ядро `compare_periods`, `filter_by_period`, `get_data_quality`, группы, `dispatch_intent` + `INTENT_REGISTRY`/`INTENT_PARAMETERS`; у контрагентов и групп есть `only_drops`.
- **Источник 1С** (`onec_source.py`): COM-подключение, выгрузка регистра и справочника в CSV, загрузка витрины в pandas. Контрольные суммы 19 313 936,63 / 22 957 182,97 / 10 878 совпали с Excel до копейки.
- **Ключевой разрыв закрыт:** в Excel-выгрузке 250 строк без даты (24,4 % выручки) → в 1С-источнике **0 строк без даты**, товарные группы из иерархии номенклатуры (27 групп у товаров, 16 в периоде).
- **Шаг 2:** Pydantic-модели DSL, системный промпт (DeepSeek/OpenAI/Ollama), офлайн-планировщик, Streamlit UI с источниками, качеством данных, таблицей, графиком и JSON-DSL.
- **Шаг 3:** UX таблиц (русские заголовки и форматы через `st.column_config` с сохранением сортировки), очистка поля вопроса «✖️», переключатель «Использовать LLM», `only_drops` у контрагентов, относительные даты в промпте и офлайн-правилах, pytest/CI/упаковка.
- **Верификация:** `python -m pytest` — **152 passed**; `smoke_test.py` — 12 разделов / 59 проверок PASSED; `smoke_llm.py` — **86 проверок** PASSED; независимый пересчёт вторым парсером — 17 сверок; внешнее ревью — PASS (замечания исправлены).

## Принятые решения

1. Выручка по умолчанию — без НДС (19 313 936,63), с НДС — режимом `gross` ([ADR 0001](docs/adr/0001-revenue-net.md)).
2. Для периодической аналитики основной источник — 1С, Excel — fallback ([ADR 0002](docs/adr/0002-onec-direct-source.md)).
3. Товарные группы — иерархия номенклатуры, эвристика — fallback для Excel ([ADR 0003](docs/adr/0003-product-groups.md)).
4. Граница LLM — JSON-DSL + `dispatch_intent` ([ADR 0004](docs/adr/0004-llm-json-dsl.md)).
5. Выгрузка 1С — отдельный шаг с CSV-контрактом ([ADR 0005](docs/adr/0005-onec-export-split.md)).
6. LLM-провайдеры — OpenAI-совместимый протокол (DeepSeek/OpenAI/Ollama), без ключа — офлайн-правила ([ADR 0006](docs/adr/0006-llm-providers.md)).
7. Версии: CHANGELOG — журнал выпусков, `pyproject.toml` синхронизируется с его верхней записью при релизе; до `git init`/публикации версия пакета остаётся `0.1.0` (на код и тесты не влияет).

1. **ИТС:** зарегистрировать УТ 11.5/ERP 2.5 на Портале ИТС, чтобы получить дословную цитату по методике; после этого обновить ADR 0001/REPORT.

3. **Товарные группы:** нужен ли уровень выше ближайшей группы (например, «Бытовая техника») в отчётах; сейчас доступны оба уровня (группа и путь).
4. **Периодичность выгрузки 1С:** по запросу или по расписанию; нужна ли инкрементальная выгрузка.
5. **LLM-провайдер:** DeepSeek настроен и проверен вручную; нужен ли выбор провайдера в UI/фолбэк на офлайн при ошибке API — открыто.
6. **LangChain-адаптер:** обернуть `dispatch_intent`/`parse_plan_json` в `StructuredTool` (следующий шаг, кандидат B).
7. **Публикация:** git-репозиторий не инициализирован; перед публикацией — `git init`, remote, проверка бейджа CI и синхронизация версии пакета с CHANGELOG (кандидат из [REPORT_STEP3.md](docs/REPORT_STEP3.md) §8).
