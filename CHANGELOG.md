## [0.7.0] — 2026-11-16 — MCP-фасад: аналитика 1С для ИИ-агента

### Added
- **MCP-сервер `onec_analyst.mcp_server` (stdio):** 12 типизированных инструментов — 7 срезов (`total`, `top_bottom_products`, `compare_top_products`, `negative_revenue`, `timeseries`, `counterparty_dynamics`, `group_dynamics`), 4 инструмента данных (`load_dataset`, `describe_dataset`, `describe_capabilities`, `list_dimensions`) и `returns_alert`. Универсальный `execute_dsl` намеренно не публикуется: произвольный JSON от модели — второй неконтролируемый контракт и расширение поверхности атаки.
- **Контракт ответа `answer_contract.py`:** обязательные «Период:» и «Данные:» (дата выгрузки, а не дата последней продажи), «Срез:», серверные итоги и отказ вместо подмены похожим срезом; параметры скрыты из чата (`ONEC_MCP_VERBOSE=1` — показать).
- **JSONL-аудит `.mcp_state/audit.jsonl`:** события `slice`, `error`, `refusal`, `dataset_loaded`, `alert`; сводка и доля отказов — `summarize_audit(days=30)`.
- **Алерты возвратов `alerts.py`:** ежедневный алерт с окном «пн = пт–вс», настраиваемым порогом, калибровкой по истории и kill switch (`ONEC_ALERTS_ENABLED`).
- **Дата данных из метаданных выгрузки:** ETL пишет sidecar `*.csv.meta.json`; загрузчик добавляет `exported_at` / `exported_at_source` в `df.attrs` ISO-строками (Streamlit-совместимо), при отсутствии метаданных — fallback на mtime с явной пометкой. Решение — [ADR 0010](docs/adr/0010-export-timestamp.md).
- **Демо-транскрипт `demo_transcript.py`:** 20 демо-вопросов с проверкой контракта (`--check` в CI).
- **Архитектурная документация:** [docs/ARCHITECTURE-SOLUTION.md](docs/ARCHITECTURE-SOLUTION.md) (TOGAF/ArchiMate + C4), 13 схем в `docs/architecture/` (`.dot` + `.svg` + `.png`, сборка `build_diagrams.py`), [ADR 0009](docs/adr/0009-mcp-facade.md) о выборе MCP-фасада вместо `execute_dsl`, диаграммы LLM- и MCP-путей в [README](README.md) и [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## [0.6.0] — 2026-10-25 — Финальный релиз: умные фильтры, стресс-тестирование, полировка UX

### Added
- **Финальная полировка фильтров и офлайн-правил:** (1) `total` с фильтром без совпадений больше не пишет «найдено 1 записей… строк в выборке: 0» — выводится «По фильтру «…» данных не найдено за выбранный период»; (2) офлайн-правила понимают паттерн «группа/категория "…"» и передают `group_filter` в `top_bottom_products`; (3) если даты не названы, `total` и `top_bottom_products` получают дефолтный период 2023-01-01…2024-12-31 либо фактический диапазон из `data_profile` — ответы предсказуемы, строки без даты не подмешиваются. Тесты: +1 display, +4 planner; итого **241 passed**.
- **Расширение DSL по итогам стресс-теста:** новые параметры — `product_filter` (`top_bottom_products`, `total`, `timeseries`), `group_filter` (`top_bottom_products`, `group_dynamics`; поиск по `product_group`/`product_group_path`), `min_base_revenue` (`counterparty_dynamics`, фильтр `period1_value >= N`). Добавлены Pydantic-поля, правила и 3 Few-Shot в промпт; офлайн-правила извлекают названия из кавычек (`«…»`/`"…"`) и число из «выручка/база больше 100к». «Средний чек / средняя выручка / средний оборот» теперь дают честный `clarification` («Расчёт среднего чека не поддерживается…») вместо подмены топом. Пустой период объясняет доступный диапазон дат («данные доступны с … по …»), а при активном фильтре сводка пишет «По фильтру «…» найдено N записей». Тесты: +7 analytics, +7 planner, +3 display; итого **241 passed**, `smoke_llm` — 92.
- **Копирование JSON из «Технических деталей»:** JSON-DSL выводится через `st.code(language="json")` — у блока есть встроенная кнопка копирования в правом верхнем углу (раньше использовался `st.json` без копирования). Под блоком — подсказка «Кнопка копирования JSON — в правом верхнем углу блока». Правка в `app.py` и `app_local.py`; тест `test_technical_details_json_is_copyable_code`. Тесты: **241 passed**.
- **Интент `negative_revenue` (отрицательная выручка / возвраты / сторно):** `analytics.get_negative_revenue(df, start_date=None, end_date=None, group_by="product")` — оставляет только строки `revenue < 0`, агрегирует по товару или контрагенту: сумма отрицательной выручки, `rows_count`, `quantity`; сортировка «самые большие убытки сверху». Зарегистрирован в DSL (Pydantic `NegativeRevenueParams`/`NegativeRevenuePlan`, промпт + жёсткое правило «не использовать top_bottom_products», Few-Shot), в офлайн-правилах (`отрицательн/возврат/сторно/убыт/корректировк`), в UI (красные горизонтальные бары, сводка «Найдено N товаров… Общая сумма возвратов: X ₽ (Y строк)»). Добавлен `guard_decision`: LLM не может молча подменить такой запрос антитопом. Поддержан диапазон месяцев «январь–июнь 2024». Тесты: +4 analytics, +5 planner, +2 display, +1 AppTest; схема — 7 интентов, `smoke_llm` — 92 проверки.
- **Rate Limiting для публичного демо:** новый модуль `rate_limiter.py` (SQLite, без внешних зависимостей) — 15 успешных вызовов LLM на сессию и 100 в день глобально; `session_id` — `uuid4` в `st.session_state`. При исчерпании лимита сессии — предупреждение и принудительный офлайн-режим правил; при глобальном — красный баннер вверху страницы. В сайдбаре — «Использовано запросов к ИИ: N/15» и кнопка «Сбросить лимит (Демо-режим)». Ошибки SQLite (файл занят) не роняют приложение: предупреждение + офлайн-правила. Путь переопределяется `RATE_LIMIT_DB`, файл `rate_limit.db` в `.gitignore`. Тесты: `tests/test_rate_limiter.py` — 12 (9 unit + 3 AppTest).
- **Интент `compare_top_products` (L4L):** сравнение топ-товаров двух периодов в одной таблице — место в каждом периоде, суммы, дельта и статус (`new`/`lost`/`up`/`down`/`same`). Решение — [ADR 0008](docs/adr/0008-compare-tops-intent.md): один интент вместо multi-intent. Затронуты `analytics.py` (функция, константы, реестр), `llm_agent.py` (Pydantic-модели, промпт, Few-Shot, офлайн-правила), `app.py`/`app_local.py` (таблица со статусами, сводка, grouped bar), `docs/intent_schema.json` (6 интентов), `smoke_test.py`. Тесты: +6 в `tests/test_analytics.py`, +4 в `tests/test_planner.py`; `smoke_llm.py` — 92 проверок.
- **Документация Graceful Degradation:** новый [ADR 0007](docs/adr/0007-graceful-degradation.md) — три уровня деградации (умный текст уточнения → лимит 2 уточнения с детерминированным fallback → честный отказ), таблица «ситуация → поведение → что видит пользователь», обоснование, альтернативы и ограничения (составные запросы не разбиваются на два рейтинга — fallback сводит к одному диапазону; счётчик уточнений — на сессию UI). Раздел 3.5 и ссылки добавлены в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), строка — в [docs/INDEX.md](docs/INDEX.md), абзац — в [README.md](README.md). Отчёт об инкременте — [docs/REPORT_STEP4.md](docs/REPORT_STEP4.md).
- **Отправка вопроса по Enter:** поле вопроса и кнопка «Спросить» помещены в `st.form` (`border=False`), поэтому **Enter в поле отправляет вопрос**, как кнопка. Кнопка очистки «✖️» вынесена за пределы формы и по-прежнему только очищает поле, не отправляя запрос. Правка в `app.py` и `app_local.py`.
- **Защита от цикла уточнений (лимит 2):** счётчик `clarification_rounds` считает уточнения подряд; после второго вместо нового круга выполняется детерминированная ближайшая интерпретация (`clarification.force_interpretation`) с пометкой «Уточнения исчерпаны — показываю как понял: «…». Если нужен другой разбор, задайте вопрос точнее.» Составной запрос («топ-5 по выручке за 2023 и отдельно топ-5 за 2024») сводится к одному показателю за общий диапазон 2023–2024; если правила тоже не могут выбрать интент, показывается понятная ошибка и список доступных вопросов. Счётчик сбрасывается после ответа/ошибки и при очистке поля «✖️». Правка в `app.py` и `app_local.py`. Тесты: `tests/test_clarification.py` (25) + `tests/test_app_question.py` (11), всего **194 pytest-теста**.
- **Quick Replies в UI + умный выбор текста после уточнения:** варианты ответа на уточняющий вопрос (`intent="clarification"`) выводятся кликабельными «таблетками» через `st.pills` (запасной путь без `st.pills` — компактные кнопки `type="tertiary"`). Выбор варианта не затирает запрос: новый модуль `clarification.py` сравнивает вторую часть с исходным вопросом — если она сама распознаётся планировщиком как полный вопрос («Сколько мы продали за 2024 год?»), в поле, расчёт и историю уходит только она; если это фрагмент («2024 год», «2023 и 2024») — склейка через пробел. Спорный случай решает LLM-классификатор (только при включённой LLM); ошибка/мусор от LLM → безопасная склейка. Правка внесена в `app.py` и `app_local.py`.
