# Changelog

Все значимые изменения проекта. Формат — по мотивам Keep a Changelog, версии — по этапам.

## [Unreleased]

### Security
- **Публичные артефакты санитизированы, бизнес-цифры закрыты стражем.** Из документации, кода и тестов убраны суммы, объёмы, диапазоны дат и номенклатура непубличной базы 1С (примеры переведены на синтетику: `sample_data.csv`, 600 строк). Имя демо-базы 1С и упоминания учётных данных удалены из документации и докстрингов. Новые артефакты: `docs/PUBLIC-DATA-POLICY.md` (что публикуется и что нет), `tests/test_public_figures.py` (маркеры непубличной базы + проверка, что каждая денежная величина в публичных доках воспроизводима из синтетики или обоснована в `tests/fixtures/public_figures_allowlist.json`), `tools/sanitize_public_artifacts.py` (идемпотентная замена, режим `--check` для CI).
- **Ложные «красные» CI исключены проверкой перед push.** Бейдж в README показывает последний прогон на `main`, поэтому любой сломанный коммит красит страницу до следующей правки. Добавлен хук `.githooks/pre-push` (включается `git config core.hooksPath .githooks`): перед отправкой прогоняются `ruff check src` и `pytest -q`; при падении push не уходит (`--no-verify` — осознанный обход). Ссылка на бейдж получила `?branch=main&event=push`, чтобы на него не влияли прогоны pull request'ов и ручные запуски. Настройка описана в `docs/RUNBOOK.md` §7.1.
- **Локальные пути удалены из репозитория и закрыты тестом-стражем.** В публичных файлах были абсолютные пути рабочей машины: `tests/golden/GoldenSet.py` (источник эталона), `scripts/load_testing_to_sqlite.py` (примеры запуска) и `.env.example` (каталог моделей Ollama). Заменены на `<путь к ТЗ>` / `<путь>` / описание без пути; история переписана (`git filter-repo`), строки удалены и из прошлых коммитов. Новый `tests/test_no_local_paths.py` сканирует отслеживаемые файлы и падает на абсолютных путях, личных каталогах (`/Users/`, `/home/`), UNC-путях и именах из локального денилиста; вымышленные заглушки и стандартные пути установки пропускаются. Имена конкретных рабочих каталогов в самом тесте не хранятся — они читаются из `.local_paths.txt` (в `.gitignore`), поэтому в публикацию не попадают. Проверка входит в обычный `pytest`, то есть блокирует повторение в CI. Правило зафиксировано в глобальных `AGENTS.md` («Никаких локальных путей в публикации»).

### Removed
- **Доработки TASK-2 (LiteLLM) откатаны из-за supply-chain инцидентов.** `litellm` дважды публиковал вредоносные релизы: `1.82.7`/`1.82.8` (24.03.2026, `.pth`-стилер — код исполнялся при каждом старте интерпретатора, даже без импорта) и `1.107.0` (21.10.2026, `.pth`-стилер и RAT, снят с PyPI через ~2 часа). Откат — revert-коммиты `59deaf0`, `51ffc70`, `d1696c9`: удалены реестр провайдеров, `llm_litellm.py`, переключатель `LLM_BACKEND` и тесты TASK-2; UI-фикс `bba0460` сохранён. Проверка окружения: `litellm` не установлен, в `site-packages` только легитимный `pywin32.pth`, кэш pip чист — заражения не было. Условия возврата (пин `>=1.110.2,<2`, deny-list `1.82.7/1.82.8/1.107.0`, `--require-hashes`, `pip-audit`, отдельное окружение) — [DECISIONS #37](docs/DECISIONS.md). `pytest` после отката — **1193 passed, 2 skipped**.

Первая занесена: «Детерминированный режим: вопрос целиком как JSON-DSL». Тесты: `test_backlog_schema_has_statuses_and_types`, `test_create_backlog_database_returns_ids`, `test_add_backlog_item_sets_properties`, `test_cli_create_backlog_requires_parent`.
- **Свойство «Ответ модели» в Notion-базе:** rich_text с компактным JSON DSL (`{"intent": ..., "params": {...}}`) — видно, что вернула модель, не открывая страницу. Для существующих баз — `--ensure-properties`, исторические страницы дозаполнены; без DSL свойство не отправляется. ADR 0016 (D18), тесты: `test_model_answer_property_keeps_dsl_json`, `test_model_answer_is_absent_without_dsl`.
- **Кнопка «Выгрузить» в UI (рядом с «Спросить»):** выгружает в Notion сессии **активного диалога** (`chat_id`), без дублей — уже выгруженные строки в выборку не попадают, повторное нажатие отвечает «Новых сессий нет». Ошибка сети/настройки показывается сообщением, страница не падает; расчёт при нажатии не запускается. Логика вынесена в пакет `onec_analyst.notion_export` (`export_chat`), `scripts/notion_export.py` стал тонкой CLI-обёрткой, добавлен флаг `--chat`. Тесты: `test_export_button_sits_next_to_ask`, `test_export_uses_active_chat_and_reports_success`, `test_second_export_reports_nothing_new`, `test_export_does_not_submit_question`, `test_export_by_chat_exports_only_active_dialog`, `test_repeated_export_by_chat_creates_no_duplicates`, `test_pending_filter_by_chat`.
- **Тестовые артефакты в `db/analytics.db` ([ADR 0018](docs/adr/0018-testing-artifacts-sqlite.md)):** `src/onec_analyst/testing_db.py` + `scripts/load_testing_to_sqlite.py`. Таблицы `test_program` (57 кейсов из «Программы тестирования»), `test_summary` (5 моделей: кейсы/пройдено/%/ошибки/p50), `test_results` (285 строк — по листу на модель, булевы `True/False/пусто` → `1/0/NULL`) и `golden_cassettes` (50 кассет: разобранные поля + сырой JSON + sha256). Импорт идемпотентен и может быть частичным; маска `test_*.json` не берёт шаблон `_example_synthetic.json`. Перезагрузка выгрузки 1С тестовые таблицы не стирает — закреплено тестом `test_refresh_of_onec_data_keeps_test_artifacts`.
- **Выгрузка 1С в отдельную SQLite-БД (`db/analytics.db`, [ADR 0017](docs/adr/0017-1c-export-sqlite.md)):** `src/onec_analyst/analytics_db.py` + `scripts/load_1c_to_sqlite.py`. Таблицы `nomenclature` (<N> строк) и `sales` (<N> строк) с индексами по дате/товару/контрагенту/группе, служебная `meta` (путь источника, sha256, время загрузки, аномалии). Загрузка идемпотентна — полная перезапись в одной транзакции. Данные кладутся «как есть»: 54 строки с будущей датой (все «Отчет комиссионера»), 11 062 с нулевой выручкой, 41 с отрицательной, 82 передачи между организациями, дубликат «Чехол Eta» — всё зафиксировано в `meta.anomalies`, а не отфильтровано. Журнал сессий и аналитика приложения не затронуты; сверка суммы `revenue_net` (SQL = CSV = <сумма> ₽) в тестах.
- **История диалога в журнале:** колонки `chat_id` (uuid разговора, отдельный от лимита LLM), `turn` (номер запроса внутри диалога) и `answer` (полный текст ответа — сводка, уточнение, отказ или ошибка; до 20 000 символов). «Новый диалог» начинает новую цепочку. Поля не входят в выборку для Notion: история остаётся локальной, витрина — только страницы сессий. Миграция добавляет колонки к существующим базам. ADR 0016 (D17), тесты: `test_dialog_fields_are_stored`, `test_dialog_chain_keeps_order`, `test_answer_is_clipped`, `test_export_does_not_receive_dialog_history`, `test_dialog_chain_links_requests`.
- **Сырой ответ модели — по флагу `ONEC_SESSION_LOG_RAW=1`:** колонка `raw_response` (до 20 000 символов) заполняется только при явном включении, по умолчанию `NULL`; в выборку для Notion не входит, промпт (`llm_request`) не хранится вовсе. Миграция старых баз добавляет колонку. ADR 0016 (D16), тесты: `test_raw_response_is_not_stored_by_default`, `test_raw_response_is_stored_when_enabled`, `test_raw_response_is_clipped`, `test_export_does_not_receive_raw_response`.
- **Сводка результата в журнале и в теле страницы Notion:** в `sessions` добавлена колонка `summary` (JSON `text`/`intent`/`values`/`periods`/`entities`/`table`), заполняется из `SummaryPayload` и снимка `DataFrame` результата (`result_table`, до 20 строк); старые базы мигрируют через `ALTER TABLE` при первой записи. Экспортёр строит блок «Результат» (текст сводки + таблица с русскими шапками: «№», «Товар», «Выручка без НДС, ₽», «Доля, %») и график по значениям результата (топ — горизонтальные столбики по выручке); PNG теперь свой на каждую страницу, а не один на пачку. Без сводки (уточнение/отказ) блок не рисуется, график показывает длительность. ADR 0016 (D15), тесты: `test_result_rows_empty_without_summary`, `test_page_body_contains_result_table`, `test_chart_uses_result_values`, `test_successful_question_stores_result_summary`, миграция — `test_old_database_is_migrated_with_summary_column`.
- **Журнал аналитических сессий (SQLite, `db/sessions.db`, [ADR 0016](docs/adr/0016-session-journal-notion-export.md)):** таблица `sessions` — одна строка на запрос (`ts`, `session_id`, `question`, `provider`, `model`, `dsl`, `status`, `verdict`, `latency_sec`, `prompt_tokens`, `output_tokens`, `degraded` + служебные `id`/`notion_page_id`/`exported_at`). Запись fail-safe: `SessionLog.record` гасит `sqlite3.Error`/`OSError` и повторяет один раз, поэтому недоступная БД не ломает ответ. `fallback` пишется как `ok` + `degraded=true`; `verdict=true` только при `status="ok"` и построенном расчёте; токены — `NULL` (контракт LLM-клиента usage не отдаёт). Хук — в `app.py` и `app_local.py` после отрисовки ответа; диспетчер, граф и `audit.jsonl` не менялись. `db/`, `exports/`, `*.db` закрыты в `.gitignore`, `.git/info/exclude` и `.dockerignore`, плюс тест-страж `test_session_db_is_not_tracked_by_git`.
- **Экспорт журнала в Notion (`scripts/notion_export.py`, вне пути обработки запроса):** читает невыгруженные сессии (`exported_at IS NULL`), создаёт страницы в базе с 8 свойствами (Название, Дата, Провайдер, Статус, Verdict, Длительность, Токены, Degraded), таблицу сводки и PNG-график кладёт в **тело** страницы (нативная table-блок + image через File Upload API). Санитизация: текст вопроса никогда не отправляется (`<PROMPT>`), ПДн-подобные строки — `<PII>`, сущности 1С в таблицу не попадают. 429 повторяется с exponential backoff по `Retry-After` (5 попыток, потолок 60 с), встроенный retry SDK отключён. Подключение (токен и адреса баз) берётся только из локального окружения разработчика и в репозиторий не входит; `--create-database --parent-page` создаёт базу и печатает `database_id` + `data_source_id` (API `2025-09-03`: схема уходит в `initial_data_source`, страницы — под `data_source_id`), `--dry-run` показывает план без обращений к витрине.
- **Ollama как выбираемый провайдер (`OLLAMA_ENABLED`):** доступность — opt-in флаг (default `false`), `LLM_PROVIDER` работает как преселект, недоступные провайдеры видны в списке с причиной («не настроен» / «выключена в .env»). DECISIONS #18.
- **Разделение галочки LLM, доступности и выбора:** при ON недоступный провайдер блокирует «Спросить» с причиной; при ON и исчерпанном/недоступном лимите вопрос блокируется, а не подменяется правилами; локальная Ollama лимитами не проверяется и не расходует внешнюю квоту. DECISIONS #21.
- **Честные ошибки LLM вместо офлайн-правил:** таймаут/сеть → «LLM `модель` не дала ответа…» с лимитом времени; невалидный ответ → «ответ не соответствует контракту»; в «Технических деталях» — запрос к модели, ответ модели и причина. DECISIONS #20, #22.
- **`llm_calls` в аудите считает и неуспешные вызовы** — инкремент на старте вызова, а не после успешного ответа. DECISIONS #24.
- **Импортированные GGUF в Ollama через JSON-адаптер (`OLLAMA_TOOLS=0`):** такие модели не умеют нативные tools (сервер требует отсутствующий `--jinja`), агент переключается на `{"tool": ..., "arguments": ...}`. DECISIONS #23.
- **Плашка «Не обновляйте страницу»** на время LLM-вызова; кнопка «✖️» рядом с «Спросить», светло-синяя кнопка вопроса, подпись «Расчёт по вопросу».

### Changed
- **График в Notion — только для успешных сессий:** у `clarify`/`refuse`/`error` результата нет, и столбик длительности выглядел случайной картинкой. Теперь PNG строится и грузится только при `status="ok"`; локальная markdown-копия пишется всегда (без PNG). У уже созданных clarify-страниц картинки удалены. Тесты: `test_no_chart_for_non_ok_session`, `test_chart_is_built_for_ok_session`.
- **Экспорт в Notion: полные локальные пути больше не отправляются.** Блок «Локальный экспорт: D:/…» убран из тела страницы: путь имеет смысл только на машине с журналом, а читателю Notion он ничего не даёт. Локальная копия по-прежнему пишется в `exports/`. ADR 0016 (D11), тест проверяет отсутствие путей в полезной нагрузке.
- **UX: кнопка «Очистить историю» → «Новый диалог» над историей сообщений, очистка в один клик.** Кнопка убрана из сайдбара и стоит в основном полотне над лентой сообщений (перед `render_history`). Сброс вынесен в `on_click`-callback (`reset_dialog`), поэтому выполняется до отрисовки: один клик одновременно убирает результат расчёта, историю сообщений, поле вопроса, `clarification_*`, `auto_submit` и `conversation_state` (раньше первый клик снимал только результат, история исчезала вторым нажатием). Кнопка отмены не показывается — очистка сразу окончательная. Правка в `app.py` и `app_local.py`; тест `test_new_dialog_button_resets_question_and_clarification_state` проверяет один клик, порядок кнопок (выше истории и «Спросить»), отсутствие в сайдбаре и отсутствие кнопки отмены.
- **Промпт агента: стабильный префикс ради KV-кэша Ollama** — `previous_dsl`/`result_entities` вынесены из system в user, system (дата, инструменты, правила, few-shot) одинаков в пределах дня. Тёплый ответ Ollama — ~7–12 с вместо ~55 с. DECISIONS #25.
- **Контекст прошлого шага передаётся модели только для вопросов со ссылкой** (`has_context_triggers`): иначе instruct-модель копировала старый DSL на несвязанный вопрос. Промпт при этом не менялся.
- **Счётчик «Внешняя квота ИИ: N/15»** и подпись «Офлайн-режим: модель не используется…»; офлайн-правила применяются только при явно выключенной галочке.

### Fixed
- **Индикатор хода расчёта над таблицей:** `notice_slot` создаётся до контейнера ответа, поэтому «Разбираю вопрос…» и «Идёт расчёт…» видны над результатом, а не за пределами экрана под ним. Регресс-тест `test_progress_notice_is_created_before_answer_container`.
- **Запуск приложения больше не ходит в сеть без необходимости:** `start_app.bat` на каждом старте выполнял `pip install --upgrade pip` и `pip install -r requirements.txt`, которые обращались к pypi.org даже при полном `.venv`, ловили read timeout, печатали `WARNING: Retrying…` и выглядели как авария. Теперь сначала локальная проверка `importlib.util.find_spec` по обязательным пакетам; если всё на месте — «Зависимости уже установлены — сеть не нужна», а `pip install` (с `--retries 2 --timeout 20`) запускается только при реальной нехватке пакетов; обновление pip перенесено в эту же ветку. `start_local_app.bat` проверяет наличие `.venv` и зависимостей и подсказывает запустить `start_app.bat`, если их нет. `PIP_DISABLE_PIP_VERSION_CHECK=1` в обоих скриптах.
- **«Ответ модели» больше не тащит подсказки-вопросы:** для `clarification` в свойство попадали все `suggestions` из DSL, и оно выглядело как склеенный список вопросов. Теперь `suggestions` вырезаются (это UI-хинты, а не ответ модели), остаются `intent`, `question`, `missing`; уже созданные страницы дозаполнены. Тест `test_model_answer_drops_ui_suggestions`.
- **Подсказки уточнения следуют за годами из вопроса:** если в вопросе назван 2022 год, детерминированные правила предлагали варианты про 2023/2024 — нелогично. Теперь `_year_aware_suggestions` берёт годы из текста (включая JSON-DSL с `2022-01-01`) и подставляет их в шаблоны; для двух лет первая подсказка — сравнение именно этих лет; без годов остаётся прежний набор примеров по интентам. Исправлено и уточнение «за какие два периода сравнить». Тесты: `tests/test_suggestions.py`, `test_clarification_suggestions_follow_question_year`.
- **Таблица результата больше не исчезает после «Выгрузить» (и любого взаимодействия):** Streamlit перезапускает скрипт на каждый клик, контейнер ответа очищается, а расчёт выполняется только при `submitted` — поэтому после нажатия «Выгрузить» ответ пропадал. Теперь последний ответ (тип, подпись, решение/данные) сохраняется в `st.session_state["last_answer"]` и перерисовывается на прогонах без нового вопроса; «Новый диалог» его очищает. Правка в `app.py` и `app_local.py`, тесты `test_result_survives_export_click`, `test_result_survives_widget_rerun`.
- **Метрика не подменяется моделью (`guard_metric`):** на вопрос «Топ-10 самых продаваемых товаров за прошлый год» GigaChat возвращал `metric="quantity"`, и ответ строился по количеству («Кабель Iota … — 420 шт.») вместо выручки. Теперь без явной просьбы о штуках («штуки», «по количеству», «единиц», «шт») метрика детерминированно становится `revenue`; интент, период, `limit`, `ascending` и фильтры сохраняются, `dsl.params` правится вместе с расчётом. Правило одно для офлайн-правил и LLM-графа; то же правило добавлено в `SYSTEM_PROMPT` (п. 13) и в промпт агента (`_AGENT_RULES`, п. 12). DECISIONS #36, тесты `tests/test_metric_guard.py` (11).
- Результат прошлого вопроса больше не остаётся под новым: ответ рисуется в контейнер с постоянным ключом и очищается каждый прогон (обход [streamlit#12069](https://github.com/streamlit/streamlit/issues/12069)). DECISIONS #26.
